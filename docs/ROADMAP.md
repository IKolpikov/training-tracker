# ROADMAP — post-MVP

Зафиксировано для памяти. **Ничего из этого не строится в MVP.** Решение по итогам обсуждения:
держать трекер примитивным, без recurrence-движка и политик переноса. Это раздел «если реально
зачешется», а не план работ.

---

## Идея: дополнительные табы Sport | Routines | Польза

Рассматривалось три таба = три политики «что показать / что считается выполненным».
Один append-only журнал (Log), пер-таб функция поведения. Sport (MVP) — частный случай.

| Таб | Откуда items | Перенос недобора | Сброс | «Сделано» |
|---|---|---|---|---|
| **Sport** (MVP) | `schedule[day]` + недельный объём | внутри недели, на не-KEY дни | еженедельно (Вс 04:00) | плавающий target (catch-up) |
| **Routines** | recurrence-правило (ежедневно/по дням) | нет | каждую новую дату | бинарно done/skip, долга нет |
| **Польза** | бэклог (всё без записи done) | полный, бесконечный | никогда | done один раз → в архив |

### Модель данных (если строить)
Таб = лист в файле = политика. Item наследует политику от таба, без per-item исключений.
(Слово «category» из ранней модели данных — выкинуто, конфликтовало по смыслу.)

```
Items: id | tab | name | recurrence
```

- `tab` ∈ `routines` | `polza`. Sport items не нужны — они в `schedule`.
- `recurrence` — только для `routines`. Для `polza` пусто.
- Отдельной `policy`-колонки нет: выводится из `tab` 1:1.

Log при этом не меняется — тот же журнал событий. Разная только функция «показать/target»:
- `weekly` → существующий `strengthTargetToday()` (catch-up)
- `routine` → `done = есть запись (item, сегодня)?`, без агрегатов
- `backlog` → `done = есть запись (item) когда-либо?` → если да, скрыть/архив

### Открытый вопрос (не решён)
Польза: done необратим, или нужна кнопка «вернуть в активные»? От этого зависит, нужен ли
в Log тип события `undone` или хватает «есть done → скрыто».

---

## Решение: НЕ делаем

Recurrence-движок + политики переноса — это инфраструктура, от которой проект как раз уходит
(«не хочу делать из этого Notion»). Keep it simple.

## Минимальный путь, ЕСЛИ позже понадобятся разовые задачи

Без второго движка, без recurrence, без политик. Один плоский лист:

```
Backlog: name | done_date
```

Отдельный таб. Чек снимается записью даты в `done_date`. ~10 строк кода. Только если реально
понадобится — не раньше.
